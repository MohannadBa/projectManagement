# بنّاء على AWS — دليل النشر

منصة بنّاء كاملة على حسابك في AWS: تسجيل دخول حقيقي، قاعدة بيانات، تخزين صور الموقع، قراءة الفواتير والمخططات بالذكاء الاصطناعي (Anthropic API)، وإرسال الدعوات بالبريد.

## المكوّنات

| الوظيفة | خدمة AWS |
|---|---|
| الواجهة | S3 + CloudFront (HTTPS) |
| تسجيل الدخول والحسابات | صفحة دخول عربية (بريد + كلمة مرور) على Amazon Cognito — لا يوجد تسجيل ذاتي؛ مدير النظام وحده ينشئ الحسابات |
| البيانات (المشاريع، الفواتير، المستخلصات، سجل التدقيق…) | DynamoDB (نسخ احتياطي مستمر PITR) |
| صور الموقع والمرفقات | S3 (مشفّر، بنسخ إصدارات) |
| الواجهة الخلفية والصلاحيات | Lambda + API Gateway |
| الذكاء الاصطناعي | Anthropic API — المفتاح محفوظ في Secrets Manager |
| رسائل الدعوة | Amazon SES |
| التحديث المباشر بين المستخدمين | API Gateway WebSocket — يصل التغيير للشاشات الأخرى خلال أقل من ثانية |
| المستندات (عقود، مخططات بمراجعاتها، مراسلات) | S3 برفع مباشر من المتصفح حتى 200 ميجابايت للملف |

## قبل البدء

1. حساب AWS بصلاحيات مدير (Administrator).
2. مفتاح Anthropic API من console.anthropic.com (اختياري — بدونه تعمل المنصة بلا قراءة ذكية).
3. بريد مرسل للدعوات، مثل `no-reply@alrasiyat.com`.

## النشر (حوالي 15 دقيقة)

1. افتح **AWS CloudShell** من شريط أعلى لوحة AWS (أيقونة `>_`)، واختر المنطقة (Region) التي تريدها.
2. انسخ المشروع من GitHub:

```bash
git clone https://github.com/MohannadBa/projectManagement.git bannaa-aws && cd bannaa-aws
bash deploy.sh --import
```

   (إذا كان المستودع خاصاً سيطلب اسم المستخدم و**Personal access token** من GitHub ← Settings ← Developer settings بدل كلمة المرور. بديل: اضغط زر Code ← Download ZIP، ثم في CloudShell: Actions ← Upload file، ثم `unzip projectManagement-main.zip && cd projectManagement-main && bash deploy.sh --import`.)

4. سيُطلب منك: بريد المالك، بريد المرسل، **النطاق المخصص** (مثل `bannaa.alrasiyat.com` — يجب أن تكون منطقته في Route 53 بنفس الحساب، أو اضغط Enter للتخطي)، مفتاح Anthropic، وكلمة مرور مؤقتة للمالك. عند إعادة التشغيل لا يُسأل مجدداً عمّا يعرفه.
   - `--import` ينقل بيانات النسخة الحالية (المشاريع الثلاثة، الأسعار، المقاول التجريبي، الدعوات). احذفه لبدء نظيف.
5. في النهاية يظهر رابط المنصة `https://xxxx.cloudfront.net/`.
6. افتح بريد المرسل واضغط رابط التحقق من Amazon SES.
7. أول دخول: افتح رابط المنصة ← ادخل ببريد المالك وكلمة المرور المؤقتة ← اختر كلمة مرورك ← تدخل كـ**مدير المنصة** (صفحة «إدارة المنصة» فقط).
8. بجانب «الراسيات» اضغط **مدراء النظام** ← أضف مدير نظامها. مدير النظام يدخل ويضيف مدير المشروع والمهندس والمحاسب والمالك. لإضافة شركة أخرى: «إضافة شركة» بالاسم والألوان والشعار ومدير النظام.

## إضافة المستخدمين (دور «مدير النظام»)

- مالك المنصة يضيف أول **مدير نظام** من صفحة «الفريق والصلاحيات».
- مدير النظام وظيفته الوحيدة: **إنشاء الحسابات (البريد + كلمة المرور + الدور)، وتعديل الأدوار، وتعيين كلمات مرور جديدة، وإيقاف الحسابات.** لا يرى بيانات المشاريع.
- كلمة المرور إما **مؤقتة** (يُطلب من المستخدم تغييرها عند أول دخول — الافتراضي) أو دائمة. يمكن إرسال بريد ترحيب، مع أو بدون كلمة المرور.
- المستخدم يستطيع: **تغيير كلمة مروره** من القائمة الجانبية، أو **إعادة تعيينها بنفسه** من «نسيت كلمة المرور؟» في صفحة الدخول (يصله رمز على بريده).
- شروط كلمة المرور: 8 أحرف على الأقل، وتحتوي أرقاماً وحروفاً إنجليزية صغيرة.
- تغيير الدور يسري عند تحديث المستخدم لصفحته. «إيقاف» يمنع الدخول فوراً.
- كل الإجراءات مسجّلة في «سجل إدارة المستخدمين».
- نطاق بريد الشركة (اختياري) يحدده مالك المنصة فقط، وعندها لا يُضاف إلا بريد ضمن النطاق.

## الحماية

| الحماية | كيف تعمل |
|---|---|
| الصلاحيات على الخادم | كل تغيير يمر بقواعد الأدوار وانتقالات الحالة في `backend/rules.mjs` (من يرفع، من يعتمد، حدود الصلاحية، فصل المهام). لا يمكن تجاوزها باستدعاء الـ API مباشرة. |
| التعديل المتزامن | كل مشروع محفوظ كسجلات منفصلة لكل منها رقم إصدار. تعديلان على سجلين مختلفين يُدمجان، وتعديلان على نفس السجل: الأول يُحفظ والثاني يُبلَّغ بالتعارض ويُحدَّث بأحدث نسخة. |
| سجل التدقيق | إضافة فقط؛ الخادم يرفض أي تعديل أو حذف، ويختم كل قيد بالوقت وهوية المستخدم الفعلية. |
| صور الموقع | لا تُفتح إلا بكوكي موقّع (CloudFront signed cookies) يُمنح بعد الدخول ويتجدد تلقائياً. |
| التحقق الثنائي | اختياري لكل مستخدم من قائمته (Google/Microsoft Authenticator). مدير النظام يستطيع إلغاءه لمن فقد هاتفه. |
| صلاحيات المشاريع | مدير النظام أو المالك يحدد مشاريع كل مستخدم؛ من ينشئ مشروعاً يحصل على صلاحيته تلقائياً. |
| جدار الحماية | AWS WAF: حد طلبات لكل IP، قائمة عناوين سيئة السمعة، وقواعد الحماية الأساسية من AWS. الـ API يرفض أي طلب لا يمر عبر CloudFront. |
| النطاق المخصص | شهادة HTTPS من ACM وسجلات DNS في Route 53 تُنشأ تلقائياً. |

ملاحظات:
- صفحات الدخول تتصل بـ Cognito مباشرة (ليس عبر WAF)، وCognito لديه حماية وحدود محاولات خاصة به.
- مالك المشروع (العميل) لا يرى التكاليف في الواجهة، لكن بيانات المشروع الكاملة تصل لمتصفحه؛ إخفاؤها على الخادم خطوة لاحقة.

## بعد النشر

- **تحديث الواجهة فقط**: `bash deploy.sh --web-only`
- **تحديث مفتاح Anthropic**: `aws secretsmanager put-secret-value --secret-id bannaa/anthropic --secret-string sk-ant-...`
- **تغيير الموديل**: أعد النشر بعد تعديل `Model` و`ModelComplex` في `template.yaml` (الافتراضي `claude-sonnet-4-5`).
- **منطقة أخرى**: `AWS_REGION=me-central-1 bash deploy.sh` (تأكد أن Cognito وSES متاحتان فيها).

## المزايا الجديدة

- **لا حد لحجم المشروع**: كل سجل (تقرير، فاتورة، قيد تدقيق، مستند…) محفوظ كعنصر مستقل في DynamoDB — جُرّب مشروع بـ 5000 قيد تدقيق وأكبر عنصر 2 كيلوبايت فقط. الردود الكبيرة تُضغط تلقائياً (gzip).
- **تحديث مباشر**: عند حفظ أي مستخدم تغييراً، تُبلَّغ الشاشات المفتوحة فوراً عبر WebSocket وتجلب الفرق فقط. إذا انقطع الاتصال تعود لفحص كل 5 ثوانٍ تلقائياً.
- **تصدير Excel**: زر «تصدير Excel» في أعلى كل صفحة (جدول الكميات، الأعمال، الفواتير، الأسعار، EVM، مستخلصات المالك، المستندات، سجل التدقيق، التقارير)، و«تقرير شامل Excel» في لوحة التحكم — ملف بأوراق متعددة واتجاه عربي. كل تصدير يُسجَّل في سجل التدقيق.
- **مكتبة المستندات**: عقود وملاحق، مخططات بالتخصص ومراجعات (A، B، C…)، مراسلات صادرة/واردة بترقيم تلقائي ومرجع الجهة، مواصفات وتقارير. كل مراجعة سابقة محفوظة ولا تُحذف، والملفات محمية (لا تُفتح إلا بعد تسجيل الدخول ولنفس الشركة).
- **عدة شركات في نشر واحد — بإدارة منصة منفصلة**:
  - **مدير المنصة** (البريد الذي أدخلته في deploy.sh، ومن يضيفهم لاحقاً) لا ينتمي لأي شركة ولا يرى أي مشروع أو ملف. يرى صفحة «إدارة المنصة» فقط.
  - لكل شركة: **الاسم، اللون الرئيسي، اللون الثانوي، الشعار، ومدير النظام**. تُطبَّق الألوان والشعار على واجهة كل مستخدمي الشركة.
  - مدير المنصة ينشئ الشركة ومدير نظامها، ويعدّل بياناتها، ويضيف مدراء نظام آخرين، ويعيّن كلمة مرور مؤقتة لمدير نظام نسي كلمته، ويوقف الشركة أو الحساب.
  - **مدير نظام الشركة** يضيف مستخدمي شركته وأدوارهم، ويعدّل اسمها وألوانها وشعارها من صفحة «الفريق والصلاحيات». لا يرى بيانات المشاريع ولا أي شركة أخرى.
  - الشركة الأولى (الراسيات) شركة عادية: بعد النشر ادخل بحساب مدير المنصة ← «مدراء النظام» بجانب الراسيات ← أضف مدير نظامها، وهو يضيف مدير المشروع والبقية.


## نقاط مهمة

- **SES في وضع التجربة (Sandbox)** يرسل فقط لعناوين متحقَّق منها. لإرسال دعوات لأي موظف: من لوحة SES اطلب **Production access**. ويُفضَّل التحقق من نطاق الشركة كاملاً (DKIM) بدل بريد واحد.
- **رموز «نسيت كلمة المرور»** تُرسل افتراضياً من بريد Cognito بحد يومي محدود (حوالي 50 رسالة). للاستخدام الواسع اربط Cognito بـ SES من إعدادات User Pool ← Messaging.
- **الصور المرفوعة في نسخة claude.ai لا تنتقل** (محفوظة هناك)؛ تنتقل البيانات فقط.
- **الصلاحيات تُفرض على الخادم**: لا يقرأ بيانات المشاريع إلا مستخدم مضاف بدور تشغيلي، ولا يضيف المستخدمين أو يغيّر أدوارهم إلا مالك المنصة ومدير النظام.
- **التكلفة التقريبية** لاستخدام شركة صغيرة: حوالي 10–12$ شهرياً لجدار الحماية WAF، و1.6$ لـ Secrets Manager (4 أسرار)، و0.50$ لمنطقة Route 53، وبضعة دولارات لبقية الخدمات (أغلبها ضمن الطبقة المجانية)، + استهلاك Anthropic حسب عدد الفواتير والمخططات المقروءة.
- **الحذف**: `aws cloudformation delete-stack --stack-name bannaa` ثم `aws cloudformation delete-stack --region us-east-1 --stack-name bannaa-edge` — يُبقي جدول DynamoDB وحاوية الصور تلقائياً لحماية البيانات.

## التشغيل محلياً (localhost) للتجربة والتطوير

يحتاج Node.js 20 أو أحدث:

```bash
OWNER_EMAIL=you@company.com node dev/server.mjs
# ثم افتح http://localhost:8080
```

نفس منطق الخادم ونفس صفحة الدخول بكلمات مرور حقيقية (مشفّرة محلياً). كلمة مرور المالك المؤقتة تظهر في الطرفية (أو حدّدها بـ `OWNER_PASSWORD=...`)، ورموز «نسيت كلمة المرور» تُطبع في الطرفية، والبيانات في `dev/data.json`. للقراءة الذكية أضف `ANTHROPIC_API_KEY=sk-ant-...` قبل الأمر. رسائل الدعوة تُطبع في الطرفية بدل إرسالها.

## الملفات

```
template.yaml          البنية التحتية (CloudFormation)
template-edge.yaml     جدار الحماية وشهادة HTTPS (يُنشر في us-east-1)
deploy.sh              سكربت النشر
backend/core.mjs       منطق الخادم والحسابات (مشترك بين AWS والتشغيل المحلي)
backend/rules.mjs      قواعد الصلاحيات وانتقالات الحالة
backend/docs.mjs       تخزين المشاريع كسجلات بإصدارات (التعديل المتزامن)
backend/index.mjs      ربط الخادم بخدمات AWS وإدارة حسابات Cognito
web/index.html         المنصة
web/claude-shim.js     صفحة الدخول وكلمات المرور، والربط بين المنصة والخادم
dev/server.mjs         خادم محلي
seed/                  بيانات منقولة من نسخة claude.ai
tools/build_web.py     يحوّل نسخة claude.ai من المنصة إلى نسخة AWS
```
